## Project Overview

GPU-accelerated search for kernel elements of the Burau representation of the braid group B_4 over F_7 (finite field with 7 elements). The search multiplies 3x3 polynomial matrices using Triton GPU kernels, iteratively extending braid words by 22 Garside suffixes and tracking elements with projlen 0 (potential kernel generators).

`braid_search.py` is auto-generated by an external `codegen.py` (not in this repo). The ~4600-line Triton kernel contains 22 unrolled suffix specializations — do not attempt to refactor the unrolled blocks.

## Commands

```bash
# Run the search (requires CUDA GPU + PyTorch + Triton)
python braid_search.py

# Submit as SLURM job (H200 cluster)
sbatch monster.sh

# Run verification tests (CPU reference vs bit-sliced arithmetic)
python test_braid.py

# Decode Garside words from saved results
python decode_words.py projlen0_results/projlen0_length042.pt
python decode_words.py projlen0_results/              # all files
python decode_words.py projlen0_results/ --verify     # with matrix verification

# Verify projlen-0 braids independently
python verify_braids.py
```

## Architecture

### Data Representation

Polynomials over F_7 use **bit-sliced encoding**: each coefficient (0-6) is stored as 3 bits (p0, p1, p2) across separate uint64 registers. A single polynomial occupies 6 uint64 values (3 bit-planes x 2 words for 128-bit capacity). A 3x3 matrix = 9 polynomials = **54 uint64 values**.

### Search Loop (`run_search()`)

1. **Seed**: 22 initial braids (identity matrix * each suffix)
2. **Extend**: GPU kernel multiplies each parent matrix by all valid suffixes (adjacency-constrained)
3. **Bucket**: Children sorted into 128 buckets by projlen value, FCFS capping per bucket
4. **Select**: Top `USE_BEST` braids chosen as parents for next step
5. **Save**: Any projlen-0 elements written to `projlen0_results/` as `.pt` files
6. Repeat for lengths 1 through `MAX_STEPS` (127)

### GPU Kernel (`kernel_braid_step`)

Each thread processes one parent braid. The kernel loads the parent's 54 uint64 values, multiplies by one of 22 suffix matrices (selected by `SUFFIX_IDX` compile-time constant), computes projlen, and writes results via atomic FCFS bucketing. Key helpers: `add_mod7()`, `negate_mod7()`, `shr128()`, `msb64()`, `lsb64()`.

### Key Parameters (top of `braid_search.py`)

| Parameter | Purpose |
|-----------|---------|
| `USE_BEST` | Number of parent braids to keep per step |
| `OUTPUT_CAP` | Max total children per step (flat buffer size) |
| `BUCKET_CAP` | Max children per projlen bucket |

GPU presets are commented in the file for H200 (80GB) and RTX 5000 Ada (32GB).

### File Roles

- `braid_search.py` — Main search kernel and host logic (auto-generated)
- `test_braid.py` — CPU reference implementation + verification tests
- `verify_braids.py` — Independent verification of projlen-0 results
- `decode_words.py` — Decode/display Garside words from `.pt` output files
- `debug_triton.py` — Diagnostic tests for Triton uint64 operations
- `monster.sh` — SLURM batch script for H200 cluster
